# 病历审阅板块（含每日汇报）

> 本工作流在根目录 `AGENTS.md` 的 ROUTES 表中对应「开发「病历审阅」板块（含每日汇报）前」那一行。

## 已定决策（2026-09-25 用户确认）

- PDF 直接上传，不脱敏；数据存原作者的本地私人服务器。全部代码最终交给原作者。
- PDF 不设容量上限：后端按块写盘，不把整份文件读进内存。
- 板块是通用的，结论只有三项：是否纳入（纳入／不纳入／待定）、病因诊断（文字）、审阅意见（文字），不带任何课题专属选项。
- 审阅人账号在原作者系统里已有，本仓库不建；开发测试只用临时库里的测试账号和假病历。
- 板块下有「每日汇报」子区：按日期排成时间轴，每条可带文字、图片和文件。
- 第二轮（2026-09-25）：手机底部「待审核」并入「通知」（分段切换），空出的位置放「病历审阅」；项目创建者拥有全部权限，可以给成员设身份（可多选）并逐项调整权限；批注支持语音批注和浏览器自带的语音转文字，企业微信的录音转文字接口等部署时和原作者一起配置；电脑端侧边栏不变。
- 第三轮（2026-09-25）：批量导入按「每个患者一个文件夹、子文件夹名即编号」；手机上选不了文件夹，只按文件名开头的编号分组。新建病历的编号默认续上项目里已有编号的最大值。审阅人和其他人的批注标记形状不同。可以设演示项目：所有登录用户都能看，非成员只能看不能改。手机底部「病历审阅」标签改为所有人都显示。

## 设计

**组织方式**：板块里先建「项目」，项目有成员。病历和每日汇报都属于某个项目，只有项目成员和管理员能看。项目创建者（或管理员）管理成员。创建者或系统管理员可以把项目设为「演示项目」（`is_public`）：所有登录用户都能看，非成员没有任何权限，被移出的成员也回到只读。

**病历**：按编号建病历，可上传多份 PDF，可指派一名有「下结论」权限的成员当审阅人。新建时编号默认取项目里末尾数字最大的编号加 1，前缀和位数照旧（FUO-009 → FUO-010）。有「下结论」权限的人都能给任何病历下结论；「指派」只决定病历出现在谁的「待我审阅」里。结论按「病历 × 结论人」各存一份，病历状态取最新一份：未指派／待审阅／待定／已纳入／未纳入。

**批注**：不写进 PDF，单独存（文件、页码、类型、位置、内容、作者，可附一段语音）。类型有点注和框选两种，位置按页面宽高的比例存（0–1），手机和电脑上都能对上。审阅人（身份含「审阅人」，或是这份病历指派的审阅人）的批注用红色方块、红色实线框，其他人用橙色圆点、橙色虚线框，由前端按项目成员的身份判断。语音由浏览器录制，优先录 mp4（苹果、安卓都能播），录不了再退到 webm；录音要求 https 或本机。语音转文字用浏览器自带识别，不支持的浏览器不显示按钮。

**PDF 阅读**：前端用 pdfjs-dist 的 legacy 构建（兼容较旧的企业微信内置浏览器）；文件经登录校验的接口取回后交给 PDF.js 渲染，只渲染视口附近的页面。

**批量导入**：纯前端，复用建病历、查病历、上传 PDF 三个接口。电脑上选总文件夹（第一层子文件夹名即编号，直接放在所选文件夹里的文件按所选文件夹名算），手机上多选 PDF（文件名开头的编号，用下划线或空格隔开）。先预览（可改编号、取消勾选、给新建病历统一选审阅人），再逐个文件上传：编号已存在就追加，病历里已有同名文件的跳过，所以中断后重导同一批不会重复；可停止、可继续、失败可重试。隐藏文件、`__MACOSX` 和非 PDF 自动忽略；同一编号下不同子文件夹的同名文件，上传名前加子文件夹名。分组规则在 `components/caseReview/caseCodes.js`。

**每日汇报**：成员发帖，填日期（默认今天）、文字、若干图片或文件；按日期倒序排成时间轴。

**导出**：项目内一键导出 CSV（UTF-8 带 BOM，Excel 可直接打开），列为编号、标题、指派审阅人、状态、结论、病因诊断、审阅意见、结论人、结论时间、PDF 数、批注数。

**日志**：查看或下载 PDF、保存结论、删除病历或文件时，写入 `review_logs`。

**权限**（照 `LOGIC_BUG_AUDIT.md` 的教训，每个接口都校验，文件下载也不例外）：所有成员都能查看；项目创建者和系统管理员拥有全部权限；其他成员可有多个身份，默认权限取并集，有「管理」权限的人可再逐项调整（存为自定义权限）。身份与默认权限的唯一定义在 `backend/app/routers/case_review.py` 的 `ROLES`，前端从项目详情接口读取。

| 操作 | 需要的权限 |
|---|---|
| 建病历、上传 PDF；改或删自己建的病历 | 上传病历 |
| 加批注（文字或语音） | 批注 |
| 提交或修改结论 | 下结论 |
| 发汇报 | 写汇报 |
| 导出 CSV | 导出 |
| 管理成员和权限，改项目，改或删任何病历、文件、批注、汇报 | 管理成员和权限 |
| 删项目；设为或取消演示项目 | 只有创建者（或系统管理员） |
| 改或删自己的批注、汇报，删自己上传的文件 | 作者本人即可（须仍是成员） |
| 看演示项目 | 所有登录用户（非成员只读） |

**后端**：模型放在 `backend/app/models/case_review.py`，接口放在 `backend/app/routers/case_review.py`（前缀 `/api/v1/case-review`），返回格式沿用 `{"code": 0, "data": ...}`。新表在 `models/__init__.py` 注册后，由 `migrate_database` 最后一步的 `create_all` 建出。

**前端**：
- 路由：`/case-review`（项目列表）、`/case-review/:projectId`（项目页，分「病历／每日汇报／成员」三栏）、`/case-review/:projectId/cases/:caseId`（病历页：左边 PDF，右边批注和结论；手机上 PDF 全屏，批注和结论从底部弹出）。
- 入口：电脑放侧边栏；手机底部标签（所有人都显示），「我的」里也保留入口。批量导入在电脑上放病历工具栏，手机上收进项目页右上角「···」。
- 基础样式放 `styles/caseReview.css`，手机样式按惯例写进 `styles/mobile.css`。
